# WarVK 1.22.01

[English](README.md) · [更新日志](CHANGELOG.md) · [地图作者 API](WarVK/README.md) · [下载](https://github.com/CallDisaster/War3VK/releases/latest)

WarVK 面向 **Warcraft III 1.27a（32位）**，使用 DXVK 派生的 D3D9→Vulkan 后端，提供太阳/点阴影、体积光、局部雾、后处理、诊断和有界 JASS API，不改变地图玩法。

## 1.22.01 重点更新

- **动态内存预算与空闲回收。** 按实际显存堆预算、已分配后备和32位地址空间余量决定扩页；Arena在GPU退役后逐步缩减空闲尾页，不释放仍在使用的数据。
- **页内空洞复用。** 同类快照不再只能等待整页全部过期；最后一个CPU/命令/GPU消费者释放后，可复用该切片区间。元数据或碎片极端情况仍有保守回退。
- **失败清理与截图内存。** 补齐图像分配/登记异常清理，保留D3D9内存块小尾段并拒绝溢出；未请求截图时不预分配读回槽，完成后的空闲槽可归还。
- 用户已对对应候选完成一轮试玩并反馈未见问题；不是所有显卡、跨地图、慢磁盘退出或长时压力都已验证，完整边界见[1.22.01说明](docs/RELEASE_1.22.01.md)。

### 继承的1.22系列改进

- **消除普通帧无用读回等待。** 精确识别无像素消费者的原生同步路径，让 CPU 准备下一帧时 GPU 继续绘制。开关性能录制均生效；真实资源 fence、Present 和不支持调用的回退保留。
- **原生截图异步化。** 按需复制到有界暂存槽，等待精确 GPU 完成信号后后台处理像素、保存 TGA。不是猜测“两三帧后肯定完成”，也不为截图每帧阻塞。
- **大地图快照页恢复。** position/UV/index 按保留寿命优先分组，失败捕获不再续期成功缓存；1.22.01进一步加入安全的切片复用，不丢弃必需投影对象来冒充恢复。
- **短时拉长阴影／撕裂修复（[#8](https://github.com/CallDisaster/War3VK/issues/8)）。** 修正旧矩阵槽位复用、组数不足及来源/坐标空间交接。坏样本已复算出异常三角形；代码修复纳入本版，所有地图的间歇异常仍需持续回归。
- **作者接口修正。** 太阳关闭停止直射及相应太阳阴影，环境光/自发光保留；修正1.27a typed JASS载体签名。显式点光、局部雾、Froxel接口保留，未实现命令明确返回不支持。
- **Render Stats 真数据面板。** Ctrl+F1查看快照页、Arena、分配预算、32位地址空间和阴影完整性；修正纯缓存命中帧的快照假零，区分Arena保留容量与上一提交代使用量。
- **渐进式架构加固。** 所有者线程推进、绑定工作代际的进度发布、公共palette计算与部分shader逻辑收口，不宣称长期重构已经全部完成。

Froxel High、局部雾、方向阴影Guide、compare-first PCF已在1.21推出，本版保留并完善，不重复算作新增。完整变化见 [CHANGELOG.md](CHANGELOG.md)。

## 性能提升来自哪里？

旧路径不是暴雪计算“每帧固定等5ms”，而是读回后缓冲时必须等待相关GPU工作完成。普通帧并不读取这些像素，却仍触发了同步。取消无消费者读回，恢复的是CPU/GPU并行及流水线吞吐，不意味着着色器少算了四成。

历史同DLL、同场景、隔离2560×1440的A-B-B-A中，平均Present间隔 **13.155→7.840 ms**：间隔缩短40.40%，应用Present吞吐增加67.78%。这是同步策略历史对照，**不是v1.21与v1.22正式版通用FPS同比，也不是输入延迟测量**。玩家另有明显收益反馈，实际效果仍取决于地图、镜头、显卡及效果。

## 运行要求与安装

- Windows 10/11，Warcraft III **1.27a / 32位**。
- 支持 **Vulkan 1.3** 的显卡和最新官方驱动；仅Vulkan 1.2不满足要求。
- 仅支持已核验游戏签名，未知布局不会通过猜地址安装Hook。

1. 完全退出游戏和编辑器，把已有 `d3d9.dll` 备份到独立目录。
2. 解压 **WarVK-1.22.01-win32.zip**，将DLL放到 `war3.exe` 同级目录。
3. 正常启动，确认 `d3d9.log` 出现 `DXVK: 1.22.01`。
4. 按 **Ctrl+F1** 打开设置与Render Stats；正常优化无需开启性能录制。

普通游玩不要继续使用旧实验启动脚本。环境变量是内部诊断面，可能覆盖默认值；玩家/作者入口为面板和文档中的JAPI。正式版**默认关闭重型帧取证**。不要叠放相互冲突的D3D9代理。

独立 **author-kit** 压缩包供作者接入JASS/YDWE，普通玩家不需要；不包含地图内DLL Loader。无需修改War3.exe、地图或MPQ。

## 如何读内存面板

- **快照页池**：可信驱动预算下动态额度默认最多512 MiB；无可信预算时回退384 MiB，已有显式上限仍生效。这不是预分配量，也不是整机显存上限。
- **Arena保留容量**：每代最多384 MiB、总上限1152 MiB；实际扩页额度可更低。已退役代际的空闲尾页会渐进缩减，但驱动/DXVK后备缓存可能稍后才释放，容量条满不等于分配失败。
- **最近扩页额度**：最近一次增长判定的结果，不是连续显存测量。显存余量与32位地址空间都会限制扩页，不保证极端负载永不耗尽。
- **上一提交代使用量**：该代游标清零前的用量，不代表GPU已经完成，也不是当前镜头模型净量。
- 静态缓存逻辑引用与快照页有重叠，不能相加。不同来源可能相差数帧；VA是地址空间，不是物理内存或显存。

## 已知边界

- **每张地图使用新的游戏进程。** 同进程退图再进图未完成发布验收（[#6](https://github.com/CallDisaster/War3VK/issues/6)）。
- 预算不是无限的，真实活跃工作集过大仍可能不能通过完整性准入；不会用错误的半份阴影覆盖完整结果。
- Issue #8修复有代码、复算和阶段性玩家证据，不等于所有间歇裂缝或历史闪退已被排除。
- 1440p/4K最坏Froxel请求可能安全回退Legacy；细小植被和点阴影表面仍可能需要特定地图的视觉检查。
- 不是所有JASS包装都已实现或逐项验证效果，应查询能力位和错误结果，见[作者说明](WarVK/README.md)。
- **不包含**未完成Water分支、原版模型自动点光接管、64位渲染器和未验收剔除/Consume实验；已有作者显式创建点光继续可用。

## 反馈与回退

提供地图名、新进程/换图顺序、画质、截图和性能HTML；也可附日志、运行状态和GPU/崩溃报告。公开前删除个人或私有地图数据。无需为了正常游玩强开重型取证。

回退前完全退出并恢复备份DLL；卸载时移除WarVK的DLL，日志另行处理。

## 开发与许可

产品/JAPI显示 **1.22.01**，后续修复继续使用1.22系列编号。Shader API保持 **1.2.0**，JASS线协议保持 **warvk:v1**，无需因产品版本升级迁移ABI。

代码位于 `src/d3d9/` 和 `src/d3d9/war3/`，shader在 `subprojects/war3fx/`，作者接口在 `WarVK/`，测试在 `AutoTest/`。正式构建使用固定依赖与显式发布选项，不复用未知诊断配置，见[发布范围](docs/RELEASE_1.22.01.md)。
