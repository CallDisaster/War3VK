## 重点：消除原生逐帧无用读回，恢复 CPU/GPU 并行

Warcraft 的一个原生帧尾路径同时服务普通帧同步与截图。在已验证的普通帧中，游戏每帧请求
一次后缓冲 LockRect，但并没有读取返回的像素。图形接口仍必须提供真正可读的数据；
当前 DXVK 因而排入后缓冲到 CPU 可读缓冲的复制，并等待相关 GPU 工作完成。

这不是暴雪按照 FPS 算出“固定等待 4–5ms”，而是数据就绪条件导致的阻塞。历史约 4.7ms
来自 QPC 在资源等待函数前后的直接计时，包含尚未完成的相关绘制/排队/读回以及完成通知、
线程调度延迟；既不是纯 CPU 计算，也不是复制一张图片的固定成本。

候选仅在精确原生代码身份、有效渲染所有者、普通同步请求且没有像素消费者时，跳过该无用
读回。真正资源 fence、EndScene、Present、帧延迟控制及不支持的调用回退保持正常。
CPU 可在 GPU 继续绘制时准备后续工作，并省掉对应的多余读回与提交；这是流水线吞吐优化，
不意味着着色器或场景算法少算四成，也不自动证明输入到显示的延迟降低。

历史同 DLL、同图、隔离 2560×1440 ABBA：

| 指标 | 原策略 | 跳过无消费者同步 |
| --- | ---: | ---: |
| 平均完整 Present 间隔 | 13.154779 ms | 7.840445 ms |
| 应用 Present 吞吐量（均值倒数） | 76.018 帧/秒 | 127.544 帧/秒 |
| 对应 GPU 资源等待边界 | 4.697431 ms/帧 | 0 |

完整帧时间减少 **40.40%**，吞吐增加 **67.78%**，约为原来的 **1.68 倍**。
两者是倒数关系：`吞吐增幅 = 原帧间隔 / 新帧间隔 - 1`。
这些数字属于历史实验 DLL EE90 的隔离对照，不是 v1.21→v1.22 正式版本同比；
不得外推到所有地图、玩家前台或显示器实际扫描帧率。最新高压图的“约40%提升”另记为玩家反馈。

配套候选已分离性能日志录制与功能开关。本集成树已完成开/关录制两轮隔离功能复验，
两态均在未设置同步开关时实际跳过普通空读回；尚非v1.21→v1.22前台性能同比。

## 截图：按需 GPU 复制，后台保存

- 原生截图事件进入有界异步队列，由渲染所有者选定正确的帧并向 staging buffer 复制。
- 后台线程须等到该槽精确 GPU 完成信号满足后才能处理像素；不能用“过了两三帧”猜完成。
- 转换与文件保存移出主渲染线程；保留原生 Screenshots 目录及 TGA 兼容形态。
- 三槽复用、尺寸/格式限制、满队列拒绝、失败记录、Reset/device-lost 隔离和不覆盖旧文件。
- CPU cached/coherent 读回内存已在实验树取得有限隔离取证，不能把后台保存时间当主线程停顿。

状态：本集成树已移植，开/关录制两态均完成单张/同帧三槽/复用的1440p文件验证和
原生EndGame→关闭窗口退出0。物理PrintScreen、全屏、分辨率变化及长时组合门仍须闭合。
2026-09-14 用户反馈其截图测试没有问题；记为该次玩家功能正向验证，未提供的场景不推定通过，
也不将旧 DLL 的结果转移为新集成 DLL 的组合验收。

## 退出与诊断窗口（候选修正）

- 不再因一条诊断输出自动创建命令行窗口；调试控制台仅显式环境开关1时启用。
- 修正控制管道thread在进程卸载时析构触发异常终止，以及性能统计在TLS销毁后再次
  读取的退出崩溃。正常设备销毁仍完整排空；进程已经终止其它线程时不再等待/读取它们。
- 该组合两轮录制开/关均退出0、无强制终止/GPU事件/新dump；不是所有玩家退出路径验收。

## 数据收集与诊断

- 为一个仅消费模型身份的路径提供固定五字段投影，避免连同顶点/索引数组复制完整记录；
  与 v1.21 已有 ready-binding 和 immutable snapshot 路径区分，不削弱其就绪/代际检查。
- 已接入 Present→Present 主线程时间线与既定入口，分开 CPU 执行、资源等待、Present 尾部与未覆盖区间。
- 已接入 DataCollection 的同根采样调用树、self/children 闭合与容量异常记录；正式配置仍按诊断门区分，
  它是已插桩入口的采样，不是整个原生线程的统计栈 profiler，也不保证全部工作已覆盖。
- 严格 JSON 根解析与重复键拒绝继续保留；不通过 parser 放宽“修复”旧无效报告。

Render Stats 原来仅显示占位文字；本轮改为按需4Hz读取快照页池、Arena、Vulkan主堆预算、
32位进程VA和阴影生产/回放/接收端统计，不需要打开性能日志或重型取证。缓存引用和页常驻
不可相加，页内占用不是当前镜头几何净量；跨来源字段不强称同帧。新面板已通过267项轻量逻辑检查、
7项静态测试和PE32 DLL构建；实机显示与正式组合仍待完成。不把增加计时入口描述为直接的 FPS 优化。

## 重点修复：短时阴影撕裂、细长暗条（Issue #8，修复已落地，待组合验证）

这项修复针对玩家报告的“一至数帧突然出现细长阴影，随后消失”，不是显示器上下画面
不同步的普通撕屏，也不是最近快照页池占满导致的全场景失影。两项分别验收，不能相互销账。

**定位到哪里：** 9月15日玩家标记的VIDEO25–29（render2188–2192）已取得顶点、索引、
蒙皮组和矩阵输入，并可独立复算出异常拉长的投影三角形：一个对应边从约17.105469变为
390.213730世界单位。地面阴影和体积太阳阴影的49组配对输入复算出相同世界角点，
说明错误几何会同时进入这两条阴影路径，与玩家看到体积雾中也出现异常阴影的现象一致；
尚无中间GPU图像/逐像素draw-ID，不能据此认证每一块暗区的最终像素归因。

用直白的话说：模型顶点还在，但用于摆放这些顶点的“骨骼/顶点组变换表”可能在交接时
不再与这个对象、这一帧匹配，少数顶点就会被拉到错误位置，形成又细又长的投影。
代码审查确认了旧槽位被重新读取并盖上当前帧标签、矩阵数量检查不足，以及替换矩阵后
来源/坐标空间没有一起更新等缺陷。它们不是“所有缓存都不该用”，也不是384MiB上限本身造成的。
其中，坏样本对应的原生槽位究竟由谁重分配仍缺直接所有权见证，不把该假设写成已证事实。

**已经怎样修：**

- 严格蒙皮路径禁止当前槽位无效时，拿记忆中的旧槽位重读全局矩阵区并冒充新数据；
  live重建只接收与当前模型、部件、帧、槽位、CPU发布代际匹配的已复制矩阵快照，数量必须够用。
- 矩阵与其实际来源、坐标空间、组数及发布身份一起交接；替换后重新核验。
  已是世界空间的矩阵不再叠乘一次对象世界变换，提交前检查是否已被新发布取代。
- 后续补齐记忆槽位的producer复核与冷/热缓存一致的组数检查。无法证明的数据拒绝本次使用，
  不靠把异常边长截短、钳制骨骼编号或关闭全部动态投影对象掩盖问题。

**当前状态：已定位异常输入及相关来源/缓存交接缺陷，修复已实现，最终发布组合待验证。**
已有生产CPU/静态测试、有限隔离运行和玩家阶段性“未再看到撕裂”的反馈；随后高压场景又报告过
裂缝/失影，且当时候选开关状态未完全核实，因此不宣布所有随机撕裂已经根治。
正式配置必须保留经审查的蒙皮正确性路径，不能在关闭重型取证时顺手关闭修复。
最终须在高压图、多实例、移动/反复俯仰及体积阴影开启场景中，同时验证“不再拉长”与
“合法对象持续有阴影”；仅没有裂缝、却把对象漏掉，不算通过。

证据与实现边界见[坏帧复算](research/2026-09-15-marked-25-29-skinning-evidence.md)、
[蒙皮来源修复合同](research/2026-09-15-skin-palette-publication-contract.md)及
[后续高压候选记录](agent-history/2026-09-16-high-pressure-fissure-evidence-candidate.md)。

## 追加发布目标：体积效果收口与全量 JASS API 校验

用户要求将已有 Froxel High、局部体积雾、方向阴影 Guide 的质量/性能收口纳入本版；
这是已发布能力的完善，不是再次声称从零新增。特别检查 2560×1440 的实际后端与预算回退、
低俯角/运动阴影边缘、局部雾体积边界和作者参数生效，保留安全回退。

9月20日当前catalog盘点为109条命令及109个对应公开JASS函数（JASS文件另有3个非命令helper），
其中feature-mask声明98条支持、11条明确unsupported。原版模型灯实验包装保留不等于本版自动灯验收。
源码测试引用覆盖76条支持命令及1条expected-unsupported，另22条支持命令未被这些测试引用；
这只是源码覆盖统计，仍须逐项验收到渲染结果，
不能用协议解析通过代替效果生效。已有 11 条 outline/bloom/postfx/aa 包装被明确标记为
UnsupportedFeature，须单列真实支持状态；全部补齐与“校验所有接口”是不同工作量。

玩家报告太阳开关无明显区别。源码已确认固定功能路径的关闭语义是停止 WarVK 覆盖、
保留原生太阳，而非消除太阳直射；其它消费者的开关语义需统一审查。
本轮已修正关闭语义，并在该测试地图及其 JASS 副本中确认直射亮度和太阳阴影的开关差异；
环境/自发光保留。另修复 1.27a 的 LoadInteger/LoadReal 签名末尾分号不匹配，避免 typed 通道
一直退回字符串协议。真实 JASS typed 数值读写与字符串回退均通过限定用例。
局部雾三形、启停/修改/销毁/8 槽上限，以及 Froxel High/Medium、低俯角和进入雾内取得功能证据。
这些是独立候选的 83 项断言（直接涉及 49 个公开函数，含一个 expected-unsupported），不是
109 API 全验收或动态 Guide/前台性能完成。旧 1440p RayMarch 16 步仍会触发安全预算拒绝，
8 步兼容设置已验证；预算未放宽。详见本轮开发记录。
详见 [工作量与验收初评](plan/2026-09-14-v1.22-volumetric-and-japi-workload-assessment.md)。
