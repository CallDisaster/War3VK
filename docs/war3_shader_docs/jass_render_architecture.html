JASS 虚拟机工作原理

入口
游戏入口初始化后，脚本执行通过 ExecuteJassFunction 进入解释器域。
执行核心
ExecuteJassFunctionInternal 负责预算切片（opBudget）和上下文准备。
主循环
JassInterpreter_MainLoop 迭代字节码，返回 completed/timeout/paused 等状态。
DXVK 接入点
我们只做“观测 + 预算调优 + Native 扩展”，保持原执行语义不被破坏。

渲染层工作原理与实际结构

当前渲染链路采用“Hook Frontend + Bridge + Pass Pipeline + DXVK Backend”结构：保持原版提交路径，同时在关键节点插入可控扩展。

flowchart LR A[WorldDispatch / RenderGroup] --> B[RenderQueueTracker] B --> C[Dispatch_Common / Dispatch_Special] C --> D[ExecBatchProcessor Begin/End] D --> E[War3Pipeline] E --> E1[ShadowReceiver] E --> E2[Outline] E --> E3[SSAO/AA/ShaderPack] E1 --> F[DXVK Backend Submit] E2 --> F E3 --> F

我们如何修改渲染层（本阶段）

1. Hook 域解耦
按生命周期/JASS/UI/Render/Shadow 分域，减少主入口耦合和定位成本。
2. 阴影链路修正
路径阻断器（LOSBlocker）通过 FourCC 黑名单从 ShadowCaster 收集中剔除。
3. 合批局部复用
Dispatch Local Merge 对连续同对象提交复用 Begin/End 上下文。
4. 本轮追加优化
Dispatch Tag/Stage 缓存：降低 GetTagStage 高频查询成本。
5. 静态阴影前移拦截
在 TerrainShadow_RegisterImageEntry 上游按来源阻断注册，而非只在末端渲染过滤。
