# WarVK v1.22 内部诊断构建：普通启动即取证

这是内部测试 DLL，不是稳定发布版。已知高压阴影消失/裂缝/偶发退出尚未闭合。
只默认开启严格蒙皮调色板来源候选与取证；不自动开启其他渲染实验、原版模型自动灯或未完成 Water。

## 使用

1. 完全退出魔兽，备份游戏目录的 d3d9.dll，然后手动替换为本包 DLL。
   包中的工具不自动替换你的玩家目录，不关闭游戏或编辑器。
2. **直接使用原来的快捷方式或 war3.exe 进入游戏，不需要 PS1、Python 或后台连接。**
3. 当前源码候选将取证显示移入 **Ctrl+F1** 的 ImGui 控制台，展开“帧取证 (Ctrl+Shift+C)”
   查看“内部诊断构建”、采集时长、失败原因及导出进度。保持之前的 2560×1440 条件。
   这项显示迁移尚未构建/部署；已交付的旧包仍显示常驻 HUD，不能混用两版说明。
4. 出现异常时按 Ctrl+Shift+C（不要求控制台打开），在控制台等待“原始包已保存”后再退出。
   每个进程一次事件；仅“图片已保存”不代表 CPU 日志和原始输入已整理完毕。
5. 默认输出：游戏目录下 `WarVK\Log\FrameEvidence`。保留 history 目录（TGA、manifest、incident）
   和同级 CPU JSON、inputs JSON、inputs.bin。incident.json 列出对应文件，勿只交图片。

控制台可用 Ctrl+F1 或窗口关闭按钮隐藏，取证面板也可折叠；**隐藏/折叠不停止取证，不释放内存**。
状态异常时核对实际 DLL 身份，以及是否保留了旧的禁用环境变量；交付包清单提供精确 SHA。
如面板报预算/空间/格式失败，不要当作正在采集；保留错误提示反馈，不要删除旧证据碰运气。

## 默认值与显式覆盖

此构建启用 Meson `warvk_internal_frame_recorder=true`。项目默认仍 false，正式构建不得继承本内部选项。
仅当以下变量**未设置**时内部构建默认1：

- `DXVK_WAR3_FRAME_EVIDENCE`：总开关；设0会同时关闭 CPU/输入/图片自动采集；控制台面板显示已关闭。
- `DXVK_WAR3_FRAME_EVIDENCE_INPUTS`：原始绘制输入。
- `DXVK_WAR3_FRAME_EVIDENCE_DRAWS`：实际阴影 draw 事件。
- `DXVK_WAR3_FRAME_HISTORY_SELF_CONTAINED`：DLL 自主调度；设0仅保留显式外部控制模式。

变量读取一次并保留整个进程；改设置需要重新启动。无效值保守地按关闭处理，不强行忽略用户显式0。
可设置 `DXVK_WAR3_FRAME_EVIDENCE_OUTPUT` 为已存在、可写的绝对目录来换输出盘。
本包不会修改系统/用户环境变量。只想测正常性能时应设总开关0再启动，不能把取证开销混入发布 FPS。

本专用候选以 Meson `warvk_skin_palette_contract_candidate=true` 编译，普通启动默认启用严格蒙皮
来源保护；正式项目默认仍为 false。需要同 DLL 旧策略对照时可在新进程显式设置
`DXVK_WAR3_SKIN_PALETTE_CONTRACT=0`。其余四项生产前提当前本来就是默认开启，不需要后台启动器。
取证和来源保护默认开启仍不代表阴影问题已经发布验收。

## 预算和验收边界

2026-09-16补充：玩家2D4B在驱动内发生空指针访问，同时显示内存不足状态；尚未证明全部根因。
当前源码已新增宿主进程VA/commit/连续块准入，但**桌面旧包和现有build32不含这项新防护**。
不要把源码说明当作已交付的新DLL；需保存当前调试现场后再构建与复验。
本高压候选把 CPU 事件环降到 65,536 条（约25 MiB），原始输入环降到224槽（上界
85.75 MiB），图片环降到96帧前窗+4帧后窗；相较旧内部档的最大宿主payload约320.5 MiB，
新上界约110.75 MiB，降低约65%。每条被保留 draw 的几何、索引、混合权重、矩阵和来源字段不裁剪；
只缩短环形时间窗。仍另保留256 MiB进程余量，预算拒绝时取证状态应报错而不是假装正在采集；
预算拒绝时取证状态应报错而不是假装正在采集。它不能保证运行中其他分配永不耗尽空间。
详见 `docs/research/2026-09-16-player-crash-pid13216-memory-admission.md`。

图片环的通用硬上限仍为4 GiB；本候选在2560×1440、96+4槽约1.37 GiB，另要求1 GiB显存预算余量。
若帧率高于约95 FPS，96帧前窗可能不足完整1秒，manifest会明确写 `durationSatisfied=false`；
短暂撕裂前后的逐帧图片和输入仍会保留，不能把该字段隐藏或伪装成一秒。
CPU/原始输入还有独立内存开销，不是零成本。进入地图前检查输出盘至少6 GiB可用；
采集中不持续写图片到磁盘，触发后才异步导出。外部程序随后占满磁盘仍可能导致部分导出失败，
部分文件会保留且明确报错，不删除或覆盖旧事件。

构建、CPU测试和隔离取证门不代表玩家前台性能、所有画质路径或长期稳定接受。
实际证据见包内开发日志及 internal-defaults-receipt.json，稳定 CHANGELOG 没有晋升本候选。
