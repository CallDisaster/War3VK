> 承接 `2026-09-18-r1-equivalence-verdict.md`（因果确证）与 `...-localization.md`（段落定位）。
> 本文回答最后一个开放问题：**反向形态是否真实存在、如何解释**。

## 1. 实测：两个方向同时存在，数量相当

对随机差分世界中的 `chain.slotIndex` 差异行逐条分类：

```
slotIndex 差异行总数           : 19
  module 供出 / legacy 拒绝    : 11   (module 恒为 slot=8)
  module 拒绝 / legacy 供出    :  8   (legacy 为 slot=4 / 11 / 7)
  双方都供出但槽位不同          :  0
```

## 2. 机制（一处改动、两个方向）

R1 只在冷缓存分支多返回一次 `0xFFFFFFFF`。该返回值**不是终态，而是路由信号**：
调用方据此跳过"按 slot 键读 Game.dll 全局 arena / QueryBlendedPaletteBySlotIndex"这条读取，
落到后续**合法的替代路径**（part snapshot / published pose 等，见 `:325-332` 既有注释）。

因此同一处改动同时产生**两个方向**的可观测差异：

| 方向 | 数量 | 解释 |
| --- | --- | --- |
| module 拒绝 / legacy 供出（slot 4/11/7） | 8 | **R1 的目标行为**：producer 的 groupCount 不足以覆盖本次所需矩阵数 ⇒ 不再供出记忆槽位。这些输入下替代路径也没能给出结果 |
| module 供出 / legacy 拒绝（恒 slot 8） | 11 | **路由的副作用**：legacy 在冷缓存"直接采用了记忆槽位"从而拒绝？不 —— legacy 在这些输入上返回了 `0xFFFFFFFF`（未供出），而 module 因 R1 提前拒绝后**落到替代路径并成功**，恒得 slot 8 |

⇒ 反向形态**不是矛盾，也不需要第二个原因**：它是"拒绝即改道"的必然结果。
**关键更正**：我先前以为"R1 只会更严、不可能让 legacy 的拒绝变成接受"，错在把 `0xFFFFFFFF` 当作终态；
它是**路由信号**，所以"多一次拒绝"可以**同时**导致更多拒绝（8 例）与新的成功（11 例）。

## 3. 这带来一个必须由裁量方回答的问题

R1 的两类后果中：

- 「不足即不供出记忆槽位」（8 例）—— 与热缓存路径既有规则一致，属**明确正当**；
- 「改道后经替代路径供出 slot 8」（11 例）—— 该替代路径本身是既有设计认可的合法路径，
  但**"因为拒绝而改走它"**是否为目标行为，需要裁定：
  · 若认为应当如此（拒绝后允许合法替代）⇒ 门禁应登记该差异；
  · 若认为不应如此（拒绝就应当整帧无 palette）⇒ **R1 的插入位置需要修改**（例如把数量检查上移，使其在替代路径之前就终止，而非改道）。

⇒ **这就是必须先取得裁定、再改门禁的原因**：两种结论对应两种不同的代码改动，不能靠改期望表糊过去。
