## 2. P0 · 确定缺陷修复（有实测依据，不属「待裁定」）

### P0-1 会话接纳边界
```
现状：war3_frame_evidence.cpp:362 setPreFreezeHook → :364 active.store(release) → :367 Arm…
      ⇒ 记录器初始化**仍在发布 active 之后**（Astra 实测：初始化前已接纳 FirstSight 但线事件 0；
        初始化后计数被清零、线仍 0、丢失计数也 0 ⇒ **无声丢失**）
要做：① 记录器初始化 + 预冻结钩子都完成后才发布 active
      ② 接纳时校验键的 sessionGeneration，旧会话在途键不得进入新会话
         （Astra 实测：旧会话键延迟到新会话执行 ⇒ 线里 session=2、对象键 sessionGeneration=1）
      ③ 四组确定性屏障：发布前 / 发布后 / 关闭期间 / 重开期间
判据：不是 armed 是否原子，而是这些交错**不再产生无声丢失或串会话事件**
探针：撤销每条修复 ⇒ 对应屏障用例**具名失败**（并打印实测数字）
```

### P0-2 MarkStage 与 maxStage 用途分离
```
Astra 实测：已知尝试号时 MarkStage 只更新 attemptStage、不更新 maxStage；
而终态阶段回填用 maxStage（evidence.h:314-315）⇒ 完整 FirstSight→S→E→D→Close 的链
终态却是 stage=FirstSight 且 sawDraw=true ⇒ **已记录绘制的链被写回「刚开始观察」**
要做：先复核实现 ⇒ 修 ⇒ 加「终态阶段必须等于该链实际达到的最高语义秩」的用例
判据：该反例不再复现
```

### P0-3 ObjectGone 不得伪造阶段、不得只处理一条链
```

      :662 用 FindOwner(key)（双链并存时只动一条 ⇒ 另一条滞留成 WindowExpired）
要做：阶段按该条链实际达到的最高秩回填；双链并存时两条都要处理，各自给终态

```

### P0-4 结算规则：仅有链首的观察链 → ObservationClosed
```
现状：evidence.h:303-308 让 hitCount==0 且 !sawServed 先落 WindowExpired
      ⇒ 我当初这么写是为了保住旧 Case 24 的断言 ⇒ **让旧错误决定新语义**（Astra 指出这是错的）
      ⇒ 而生产 d3d9_device.cpp:23539-23548 **故意不发 Served**（无选中 palette 不得凭空造事实）
        ⇒ 真实序列 FirstSight→Enqueued→Close 会被结算成 WindowExpired
要做：仅链首后关闭的观察链 ⇒ ObservationClosed（**诚实报告缺绘制证据**）；
      **更新新版本测试的正确期望**（这是修契约，不是放宽判据）
判据：FirstSight→Close 与 FirstSight→Enqueued→Drawn→Close 都得到 ObservationClosed
```
