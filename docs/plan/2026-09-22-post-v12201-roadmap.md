# v1.22.01 之后的推进计划

状态：2026-09-22 只读复核后的建议路线图。本文不授权自动构建、部署、实机或发布。
基线：主目录 `dxvk`，HEAD `a2054a9`；产品源码发布提交 `7e28156` / 标签 `v1.22.01`。
复核开始时只有用户 `subprojects/StormBreaker` 既有 dirty，未用于构建或修改。

## 1. 当前阶段与目标

我们已有已发布的 v1.22.01 基线；接下来不是重新做发布整合，也不是把所有长期计划塞进下个补丁。
主目标是：**保持阴影正确与故障可恢复，减少每帧实际收集/复制/分配量，同时逐条统一数据选择和资源寿命。**

已落地的工作不重复立项：

- A/B 主目录整合、正式/诊断配置区分及发布包校验。
- 快照按寿命分页、最后消费者持有的切片租约、退役区间复用。
- 实际 heap budget / 物理后备 / Win32 VA 共同约束的动态扩页额度，以及 Arena 渐进缩页。
- Image 失败清理、D3D9 小尾段/溢出边界、截图按需分配与空闲槽回收。
- 构建所有者门、工作身份与代际、按值进度发布；M1/M2 的部分职责迁移、Shader 公共化。
- S2 调用方容量复用与局部扫描成本修正；仍不能称所有热路径零分配。

接受边界：对应候选有玩家单轮正反馈，正式版离线 CPU 99/99、静态 275/275。
没有完整的全 GPU、跨地图、慢磁盘、长期运行或最终组合 Issue #8 验收；也没有本版新增 FPS 收益数字。
09-19 的“实现约60% / 验收约40%”属于旧管理估算，不能当作今天的测量值；本计划改按工作包收口。

## 2. 优先级与工作包

### R1：巩固正式基线，先让验证能复用

**第一批工作。** 固定 v1.22.01 正式 DLL、配置、地图、相机路线与 2560×1440 条件，
复用现有 AutoTest 和报告，不再先建一套大型取证框架。

- 常规图与高压大图：固定地点、移动到多个区域、低视角施压、移开、返回、恢复。
- 先测重型诊断关闭的真实使用配方，再单独测截图/轮廓/体积阴影/取证相关消费者共存。
- 记录完整帧耗时及 p95/p99、峰值与稳态内存、压力解除后的回落过程；
  分清有效存活字节、页容量、allocator 保留后备与进程 VA，不能相加成一份占用。
- 核对 required caster、生产完整性、阴影图更新、GPU incident/device lost，以及真实画面。
- 原生截图首次/连续请求、录制开关、窗口尺寸变化与退出分别验收；正常盘与慢盘不是同一个门。

完成条件：可重复的路线和原始报告绑定正确，失败能定位到阶段；结果分别写清 CPU/GPU/玩家证据。
性能回归门的容差先按基线波动冻结，不能在候选失败后调宽。
尚不能自动操作的难度选择/ready 必须明确解决，不能用“进程启动了”替代进图。
没有最新性能基线之前，不先断言当前最大耗时仍是历史某个函数。

### R2：两个有明确反例的维护项，分别提交候选

1. **对象证据跨 attempt 拼链。** 当前 `Recovered` 汇总累计 sawServed/sawSubmit/sawDraw，
   新尝试仅重置判序，可能把几次不完整尝试拼成恢复。
   修复应绑定同一次尝试的最终来源、入队与 draw；保留“拒绝后下一次合法尝试恢复”的正例。
   未知身份仍不得认证同对象，命令已记录不升级为像素恢复。
   验收：真实生产记录器→导出→解析器往返，覆盖跨尝试假阳性、完整正例、重试、丢事件与 Reset。
2. **慢 I/O 退出。** 截图已按需分配，但同步 WriteFile + 析构 join 仍可能拖住关闭。
   先冻结取消/完成/缓冲所有权合同，再实现；取消请求不等于 I/O 完成，不能 detach 后销毁在用对象。
   验收：生产链的慢写、失败、退出中断、完整文件和资源保活；拒绝取消的情况如实保留边界。

这两项主要改善诊断可信度与退出可靠性，不宣传为 FPS 优化；不与阴影算法或剔除调整混成一包。

### R3：内存优化从“能回收”转向“本来就少采、少复制”

先利用 R1 的账户定位复制/分配大头，而不是继续扩池。

- 选择一条有真实命中的来源，比较实际索引引用域与被复制的 VB/IB/UV 区间，处理范围放大。
- 区分不可变模型几何、当帧姿态和 draw-time 输入；缓存复用必须具备身份、版本、空间与有效期，
  不能把动态数据简单放进永久模型缓存。
- P2a 摘要消费者已存在，但历史实机命中为 0：先解释生产覆盖和旁路，禁止直接开默认并算收益。
- 继续评估切片表饱和、空洞不连续与真实活跃集合超预算；只有量化为主要原因才引入新策略，
  不预先建设复杂压缩/搬迁器，不抢回 GPU 在用数据。

完成条件：同一覆盖与画质下，实际复制字节/分配次数或稳态占用下降，
完整帧及尾延迟无显著回归，压力后合法阴影持续恢复；不以预算增加或丢 caster 作为成果。

### R4：把长期架构重构落在两条真实生产链上

**先 Registry/M3，再一条 CurrentDraw/M4；每条链可独立回退。**

1. persistent geometry 的 lookup→准入→创建→GC/reset：将输入明确的判定与设备资源原语分开，
   保留 Present/GPU 退役所有者；补 domain 字节/条目账户。
   现已有 domain 字段、owner-check 和报告计数，缺的是完整身份键/账户/运行验证，不是从零实现。
   domain 是否进入 key 单独评审，不夹带 Stage13 常驻路线或 alias 大迁移。
2. 选择一个真实活跃 CurrentDraw producer：几何、palette、材质、坐标空间、对象身份、
   帧/地图/设备代际和保留引用一起交接，经唯一验证入口交给消费者。
   逐步移除 ValidationBackend 对 host 重复决策的依赖，不只把代码搬到新文件后再回调 device。

完成条件：同 key 跨域、同地址重用、旧工作晚到、缺 palette、失败后账户守恒、
GPU 完成前不可回收，以及合法对象恢复的生产交接测试通过；随后完成适用的实机不劣化门。
架构成果以减少了哪个决定入口/旁路、哪项检查变得不可绕过计，不以迁出行数计。
全局跨 Pass 合同仍是后续工作，不能把已完成的快照切片租约说成完整资源图。

### R5：有证据的提前筛选，而不是直接打开旧剔除开关

当前实验对象/terrain/union Consume 未晋升；最终 CSM 层的剔除晚于快照申请，
即使少画了几次，也不会自动节省此前捕获成本。已有可信索引的缩域保留，不笼统称“没有剔除”。

- R3 证明捕获范围仍是大头后，才研究捕获前或重复制前的保守筛选。
- 同时考虑 surface/volume/point 等消费者；镜头外物体仍可能向可见区域投影。
- 第一批限于身份/版本可证的静态刚体 bounds；动态/蒙皮/未知保持可见，不用猜测 bounds 拒绝。
- Observe 与旧路径差分先闭合，再单独批准消费；不得重新采集一遍昂贵几何只是为了决定不采集。

完成条件：移动、低视角、体积阴影与阴影边缘不漏投影；实际捕获成本和总帧时有净收益。
若收益仅在最后绘制阶段，准确记为 GPU draw 减量，不记为快照/Arena 减量。

### R6：配置和作者功能的兼容收口，可与主线离线并行

- 重新核对当前生产/实验/测试开关及责任模块、默认、读取时机、重启要求、面板/JAPI 优先级，
  复用已落地的正式配置 verifier；不机械删除开关，不改变默认来简化清单。
- 玩家主入口继续是 Ctrl+F1 与 JAPI；env 作为内部面按既有裁定管理。
- 根据当前公开接口重新生成覆盖表，先补太阳开关、局部雾、Froxel、Guide 的组合/重设用例，
  再推进其他公开 API；旧“49函数/83断言”不外推为全量 API 可用。
- 原始坏帧、修复来源与最终组合视觉回归绑定，Issue #8 保持“针对已定位路径修复，全面复测待补”。

完成条件：可见支持/未覆盖矩阵，配置实际生效与文档一致；新/失联开关及 API 接线回归能被测试发现。
同进程 A→B→A 作为单独生命周期验收项目；通过前保留每图重启建议，不混在普通冷启动结果中。

## 3. 近期执行顺序与分工

1. **下一轮：R1 最小可复用基线 + R2 的跨 attempt 独立小修。** 若基线发现 GPU 错误或失影复现，
   自然故障优先，保留证据，暂停其他渲染候选。
2. R2 慢 I/O 单独设计/候选；R3 依据实际账户只选一个最值钱的减量点。
3. R4 跟随该生产链收紧职责，R6 的清册/测试可并行，不同时改写四套生命周期。
4. R5 以范围、身份和消费者覆盖为前置，不作为短期默认启用项。

主线程负责来源/所有权/回退与实机结论；子任务适合清册、定向反例、文档和独立审查。
同一热路径只有一个写入所有者；源码冻结后统一构建验证。
每批更新开发日志，实施/离线/GPU/玩家结果分列。小修适合后续 1.22.x；
大范围职责变化单独候选验证，不承诺一个补丁完成整个长期重构。
