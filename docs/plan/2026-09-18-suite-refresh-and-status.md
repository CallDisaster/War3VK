## 3. 为什么不把目标标记为 blocked

策略要求「blocked 仅在**同一阻塞条件持续**且**已无有用工作**时报出；**仍有有用剩余工作不算 blocked**」。

本目标**确实还有不依赖实机的有用工作**，至少两项：

| 剩余工作 | 说明 |
| --- | --- |
| 解析器侧的**正常链**集成测试 | 复审要求"用实际生产入口完成**两类链**的最小集成测试"。目前**记录器侧**已有 Case24（宿主 C++），但**解析器（Python）侧**只有静态门禁，缺一份"喂入 v3 合成导出 → 断言正常链判定"的测试 |
| 版本 3 导出往返的读方见证 | 写方已按 `firstSightUsed() ? 3 : 2` 抬版本，但**尚无**读方在 v3 下走完整判定的用例 |

因此本轮**不**标记 blocked；实机部分记为"外部依赖未满足"，其余继续推进。
