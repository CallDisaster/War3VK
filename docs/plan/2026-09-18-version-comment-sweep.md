## 2. ★ 新发现（三处，均已修；两处是**真缺陷**）

### (a) `war3_frame_evidence.cpp:75-79` —— **"补新不删旧"的第 5 例，且在同一文件里**

该处有**三代互相矛盾**的叙述叠在一起：

```cpp
// …因此头块版本必须是 **2**（版本 2 = 现行生产形状）。        ← 第 1 代（D2）
// …写方只在真的发过首见事件时把块版本抬到 3；未使用首见链的导出仍是 2。  ← 第 2 代（批次 3）
// 2026-09-18 阶段 C：**恒定 v4**。                            ← 第 3 代（阶段 C）
result["version"]=4;                                        ← 代码真相
```

⇒ 第 1 代那句「**因此头块版本必须是 2**」在当前代码下是**错的**；读者要读完 10 行才知道。
⇒ **round 80 我只修了 `:63-66`（同一文件、同类问题），漏了这一段** —— 这本身说明
   "逐处修"会漏，需要**成段扫**。

**修法（保留历史，不删除任何一代）**：在三代之前插入标注：

```cpp
// 【历史 × 3 代】下面这段（D2）→ 批次 3 → 阶段 C 是**同一处的三代叙述**，它们互相矛盾是**正常的历史**：
//   第 1 代说"因此头块版本必须是 2"；第 2 代说"抬到 3"；第 3 代说"恒定 4"。
//   **现行事实只有一条：本函数恒定写 `version=4`（见下方 result["version"]=4）。**
```

### (b) `war3_frame_evidence.cpp:106` —— 措辞会被误读

```cpp
- // 因此这里保持版本 2 的注册形状不变。
+ // 因此这里保持**同一套注册字段集合**不变（版本号现为 4；不因这些诊断量而增删字段）。
```

原句的**本意**是对的（"不因诊断量而增删字段"），但"版本 2"三字会被读成"版本号仍是 2"。

### (c) `war3_palette_object_evidence.h:848` —— **悬空引用**（新子类）

```cpp
- // 语义秩 ⇒ 阶段（终态记录回填用；见 CloseWindow 的版本 3 分支）。
+ // 语义秩 ⇒ 阶段（终态记录回填用；见 CloseWindow 里的 `e.sawFirstSight ? StageOfRank(e.maxStage) : Drawn`）。
```

**核实**：读 `CloseWindow`（`:278-325`）—— 它按 `e.sawFirstSight` 回填（`:314-315`），
**与版本无关**，**没有**"版本 3 分支" ⇒ 原注释指向一个**已不存在**的代码路径。

**子类定义**：不是"注释与代码矛盾"，而是**"注释指向的代码路径已不存在"** ——
这是"补新不删旧"的**变体**（重构时路径没了，引用它的注释留了下来）。

## 4. 我**未**改的一处（以及理由）

`evidence.h:313`「拒绝恢复链（**版本 1/2 冻结行为**）仍写 Drawn，一位不改」：

- 它的**语义是对的**：该分支只由 `e.sawFirstSight` 决定，与版本无关，作者想表达的是
  "这条链是**旧有**行为、不要动"；
- 但"版本 1/2"这个措辞在**恒定 v4** 后会造成"读方按版本分支"的错觉；
- **未改**的理由：它**不是矛盾**（没有一句会与代码冲突），只是措辞；
  而 round 70 的教训是"**散文类改动容易改坏**"⇒ 对**无害的措辞**不动比动更稳。
记录在此，供将来统一措辞时一并处理。

## 5. 提炼（本轮新增两条规律）
