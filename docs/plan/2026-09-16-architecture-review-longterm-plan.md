## 总目标

在不破坏现有验证纪律的前提下，完成架构复审剩余的主体工作：
统一两棵开发树、实机验证 palette 收紧、把 War3 语义选择职责迁出 `d3d9_device.cpp`、
完成 397 个运行时开关的三分类，并建立防止回退的固定门禁。

## 阶段 0 — 前置决策（用户拍板，agent 只准备材料）

- 内容：`dxvk`（当前主树）与 `dxvk-v1.22-integration-20260914`（复审快照线）的合并/分工。
- agent 可做：生成两树差异清单（源码、测试、文档三视角），标注各自独有工作与冲突点。
- 完成标志：用户明确主树；另一棵树的独有工作有逐条"合入/放弃"记录。

## 阶段 1 — palette 收紧的实机门（阻塞后续部署）

- 内容：当前工作树的 palette slot 身份证明复核（fail-visible 收紧）尚未实机验证。
- 做法：高压光影图（"生与死"或同等）巡航，关注
  `semanticScenePaletteSlotProvenanceMismatchCount` 是否非零、是否有可见姿态回退/闪烁。
- 完成标志：至少一轮高压图运行中无可见回退；若计数器非零，定位失配来源并确认属"真重用"
  而非误伤（误伤则按文档规则收窄规则后重测）。
- 边界：部署与启动游戏必须有用户明确请求，先核验进程与备份哈希。

## 阶段 2 — 数据身份验证入口（复审阶段二主体）

- 范围：
  1. producer 表 stale-binding 窗口（`war3_model_hook.cpp` 层：指针被重用但新对象尚未捕获时
     仍命中旧 binding）；
  2. 把"本次绘制使用哪份 palette"的验证收归一个入口——几何、分组索引、矩阵、对象身份、
     有效期经一个入口检查后形成可用结果，下游不能悄悄替换其中一块还沿用原标签。
- 约束：借鉴已有的私有凭据（recording authority）与完整代际检查（point shadow prepare worker）
  模式，不新造架构名词；一次只动一条数据链。
- 完成标志：同一地址被另一对象重用、矩阵数量不足、旧帧结果晚到这三类情形都有
  能抓住接错线的测试；正常实例不被误伤。

## 阶段 3 — 职责迁移与配置三分类（复审阶段三）

- 范围：
  1. `d3d9_device.cpp`（45,682 行）中的 War3 语义选择逻辑逐步迁出：设备入口只接 API 调用、
     取输入、调语义模块、执行提交；"选哪份矩阵/是否接受旧快照/走哪条备用路径"由明确模块决定；
  2. `DxvkValidationBackend` 的占位 handle + host 回调收口（迁移完成后原入口失去做该类决定的能力）；
  3. 397 个 `DXVK_WAR3_*` 开关分为"正式支持/开发实验/待移除"三类；已稳定替代旧路径的实现
     经对照后退休旧路径。
- 完成标志：修改一条蒙皮选择规则只需理解一个模块；相关选择逻辑可在不启动游戏、
  不创建 GPU 设备的情况下测试；开关清单落盘为文档。

## 阶段 4 — 跨 Pass 资源管理（复审阶段四后半，可延后）

- 挑一条范围明确的链路（surface 阴影 + volume 阴影），明确每个资源由谁产生、被谁读、
  何时可复用；利用现有 DXVK 资源跟踪，不另造状态系统。
- 完成标志：资源读写顺序有明确维护位置；不一致能在构建或测试中发现。

## 固定门禁（每个 checkpoint 必过）

1. `build32_safe.cmd src/d3d9/d3d9.dll -j8` exit 0 + `ninja -C build32 -n` no-work。
2. `meson test -C build32` 全过（当前基线 28/28）。
3. AutoTest `test_*_static.py` 全量通过（当前基线 88/88）。
4. 每次形成结论同 checkpoint 更新 `docs/agent-history/DEVELOPMENT_CHANGELOG.md`；
   候选/判退不得冒充稳定更新。
5. 不改玩家现场、不部署、不启动游戏，除非用户明确请求。

## 子代理路由纪律

- 复杂任务 → `provider: cli-proxy-api, model: grok-4.6`；
- 简单任务 → `provider: cli-proxy-api, model: gemini-3.8-flash-high`；
- 禁止省略（省略 = 占用主模型 kimi-k3 额度）；`subagent_fork` 固定路由不可选。

## 明确不做

- 不推倒重写；不引入完整 Render Graph 作为万能解法（复审已论证它解决不了对象错配）；
- 不为减少文件数强行合并坐标空间/执行阶段不同的 shader 函数；
- 不以"再加一百个测试"为目标——目标是每种重要交接都有一个能抓住接错线的测试。

## B. 三个真正的卡点（用户定义，本计划围绕它们排）

1. **“足够新”≠“属于这个对象”**：帧号/数量/范围检查不足以证明槽位未被别的对象重新占用
   ⇒ 需要**槽位所有权见证**或**有界对象级记录**证伪，不是再加计数器。
2. **知道拒绝了，却不能追踪该对象之后如何**：是否正确回退、是否漏阴影、压力解除后是否恢复
   ⇒ 需要**有界对象级证据链** + 四项活跃路径计数（路径到达/提交分母）。
3. **公共函数抽出了，但最终决策权仍分散**：S2 统一的是计算不是来源选择与生命周期
   ⇒ 需要**可复现差分工具** + **分配/扫描成本口径**，再谈统一入口。
