## 点光接入：必须是真实 producer，不再停在无消费者快照

1. 冷加载：核 Game.dll 全内容身份与各 Hook ABI；实际成功读取的 bytes/size/path 与 parsedDocument
   精确关联。MDL→MDX fallback、缓存、预加载、嵌套、异步加载需明确；不使用 last-path TLS 猜关联。
2. 文档→模板→实例：给每次生命周期独立非零 generation，保存自有有界元数据；
   parsed Light ordinal、ObjectID、graph index 与 outputSlot 分别验证，不相互代用。
3. 运行值：读取游戏已求值的世界位置、颜色、直接/环境强度、启停；+0x28 是 selectionScore，
   不能当范围。MDX 衰减动画与最终原生 D3D9 设备衰减不是同一字段，映射须有明确合同。
4. 发布：在既有渲染所有者安全点产生独立值快照；原生裸指针不可异步解引用。
   删除、缺帧/未求值、地图/设备失效、同址复用、容量溢出均安全撤销，不无限保留旧灯。
5. 照明：单独处理原生固定功能贡献替代，防止重复增亮；不能禁掉所有 SetLight 误伤太阳/环境光。
   原有 JAPI 灯不被覆盖/夺号，不强行挤出作者灯。
6. 阴影：初始候选仅9路径/11资源版本，精确 path/SHA/size/ObjectID；试验最多2盏自动阴影，
   共享现有总预算，超额只不投影而不能压垮帧时间。预算最终以视觉/性能门决定，不视为已启用。
7. 计量：顶层 NativeModelLights 时间向下分为加载/绑定/求值采样/选灯/发布与拒绝原因。
   不逐 draw 解析文件/算SHA/扫全场；记录灯数量、实际shadow-selected、缺身份/失效/满额。
