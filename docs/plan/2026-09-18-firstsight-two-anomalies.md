# FirstSight 的两个疑点（实机数据）— 2026-09-18

## 数据（`cpu-31736-28653959291-1.json`，`DRAWS=0` 运行，`evicted=0`、3691 条 palette 事件全保留）

```
stage counts  : FirstSight = 1304    Enqueued = 1299    Drawn = 1088
distinct keys : FirstSight =   32    Enqueued =   32    Drawn =  107
```

## 疑点 1：两个采集点覆盖的**对象集合不同**

```
生产采集点 (d3d9_device.cpp:23505-23533)  -> FirstSight + Enqueued  -> 只覆盖 32 个对象
阴影渲染点 (d3d9_war3_shadow.cpp:5252)   -> Drawn                  -> 覆盖 107 个对象
```

⇒ 只有 **32/107** 的对象能同时具备"链首（FirstSight）"与"Drawn"，
所以 75 条链在解析器眼里只有 `Drawn`、被判 `rejectedStageMissingFromStream`。

**这不是解析器的问题，也不是环淘汰的问题** —— 是**生产采集点没有为那 75 个对象发出链首**。

## 疑点 2：`FirstSight` 名实不符（我认为这是缺陷）

```
32 个对象 -> 1304 条 FirstSight 事件  ≈ 41 条/对象
32 个对象 -> 1299 条 Enqueued   事件  ≈ 41 条/对象
```

阶段名是 **FirstSight（首次观察）**，但**同一对象被反复发出约 41 次**。
若"首次观察"应当**每个对象恰好一条**，则当前行为与命名不符；
若它实际语义是"本帧在生产点看到该对象"，那**名字与文档都在误导**，
而且它就不是"链首"（链首应当唯一），解析器把它当链首使用会掩盖真实语义。

两种可能都不好，**必须查清**：

| 可能 | 若成立应观察到的现象 |
| --- | --- |
| A. `NoteFirstSight` 本就每帧发射，名字错 | 记录器内有"同对象同帧同阶段去重"（`droppedDuplicatePerFrame`），跨帧则每帧一条 |
| B. 本应"每对象一条"，但去重按 `(对象,帧)` 而非按对象 | 同一对象在多个帧各留一条 ⇒ 与观测一致 |

## 为什么这两点重要

目标 ③ 的原话是「**首次观察**→候选入队→draw已记录→窗口结束」。
- 若"首次观察"实际每帧重复，则这条链的**语义**与复审要求不符；
- 若生产点只覆盖 32/107 个对象，则这条链**覆盖不全**；
两者都不是"改解析器"能解决的，也不该靠放宽判据掩盖。

## 与既有约束的一致性

值得强调：**我不打算为此放宽任何判据**。
当前解析器对 75 条链报 `Uncovered` / `rejectedStageMissingFromStream` 是**正确**的 ——
因为那些链**确实**缺链首。要让它们变成"完整"，只能让**写方真的为这些对象发出链首**，
而不是让解析器假装没看见。

## 待子线程 D 回答

3. 生产采集点为何只覆盖 32/107 个对象（是否有前置条件把它限制在某个子集）；
4. 若确认语义错位，**最小修正点**在哪里。
