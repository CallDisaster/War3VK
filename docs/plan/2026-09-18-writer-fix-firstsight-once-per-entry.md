# 写方修正①：首见去重按**条目**（消除每帧重发）— 2026-09-18

> 子线程 D 定案：`FirstSight` 每帧重发**不是本意、是 bug**（去重维度是 `(对象键, renderFrame)`）。
> 本文记录实施与验证。

## 1. 改动（一处条件 + 清理一个死字段）

`src/d3d9/war3/tools/war3_palette_object_evidence.h`：

```cpp
// 修复前：按 (对象键, renderFrame) 去重 ⇒ 跨帧不去重
} else if (e->lastFirstSightFrame == frames.renderFrame) {
  m_counters.droppedDuplicatePerFrame++;
  return;
}

// 修复后：按**条目**去重 ⇒ 每对象每观察窗口恰一条链首
} else if (e->sawFirstSight) {
  m_counters.droppedDuplicatePerFrame++;
  return;
}
```

并**删除**了 `Entry::lastFirstSightFrame`（含其唯一写入点）。原因：改动后它**只写不读**，
留着一个叫「同帧去重标记」的字段会让后来者以为去重仍按帧进行 —— **误导性遗留比缺失更糟**。

## 2. 设计决策：**复用**计数器，不新增 wire 字段

| 选项 | 取舍 |
| --- | --- |
| **复用 `droppedDuplicatePerFrame`**（采用） | 零 wire 变更、零读方变更；代价是名字里带 "PerFrame" 而含义扩展为「已发过链首的条目又被重复观测」 |
| 新增 `droppedDuplicateFirstSight` | 名字更准，但要动 wire 计数字段 ⇒ 又一次**三方读方同步** |

**选复用的理由**：我在 v3 上刚踩过「写方加了字段、读方只注册旧版本 ⇒ 整份导出被拒」的坑（`PALETTE_OBJECT_BLOCK_FIELDS` 精确相等校验）。
为一个计数器的名字去冒同类的风险不划算。语义写在代码注释里。

## 3. 修复的真实效果（机制层面）

```
修复前：生产采集点对每个提交 caster、每帧调 NoteFirstSight + NoteEnqueued
        ⇒ 每对象每帧吃 2 个非终态配额
        ⇒ 每帧只有 64/2 = 32 个对象拿到链首
        ⇒ kNormalBudget=3584 迅速打满（实测 emitted−terminal 恰好 = 3584）
        ⇒ 后出现的 75 个对象「有条目、有终态、零阶段事件」

修复后：每个条目只在**首次**观测时发一条链首
        ⇒ 配额压力从「每帧 2N」降为「每对象一次性 2 条」
        ⇒ 75 个对象有条件拿到链首
```

**注意**：这是**机制层面**的改善。我没有实机重测来证明 32 → 107 —— 那需要再跑一次采集（并重新走一遍部署/恢复链）。

**值得注意**：修复后**没有任何测试失败** ⇒ 说明**此前没有任何测试断言"每帧重发"行为**。
这与审计的结论一致（v3 的门禁很薄），也说明这个 bug 能存活至今正是因为**没有测试覆盖它**。
