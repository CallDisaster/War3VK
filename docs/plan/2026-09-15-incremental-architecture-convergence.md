# WarVK 渐进式架构收敛计划

状态：2026-09-15 用户认可的长期实施约束；不是架构重构完成报告，也不授予额外运行权限。
适用：本 v1.22 集成工作树中涉及渲染数据、资源生命周期、诊断或相关测试的修改。
入口见 [AGENTS.md](../../AGENTS.md)。不自动改写其他分支或工作树。

## 目标与执行尺度

在解决真实问题的同时，逐步减少同一事实的多个来源、重复决策、身份与实际输入脱节以及难以验证的跨层交接。
每轮选择一条可验证的数据链，不把“拆成更多文件”当作完成目标，也不为了统一架构同时重写来源、缓存、同步和着色算法。

允许两种结果：

1. 与本问题直接相关的边界能安全收紧：随修复实施，但以独立差异和验证记录区分修复与结构调整。
2. 收紧会扩大风险或缺少验证条件：先完成可验证的最小修复，登记残留债务、风险与再次处理条件，不强行扩张。

不要求每个拼写、文档或局部修复都开展架构工程；要求不再无说明地增加新的长期旁路。
紧急修复如必须临时增加路径，应明确启用条件、回退、责任模块与退出条件。

## 数据与职责合同

### 1. 真正收拢决策，而不只搬动代码

- 明确入口负责收集哪些原生事实、谁负责解析和校验、谁签发可用输入、谁只负责消费。
- 逐步将巨大设备类中的来源选择和策略决策移到明确的模块；不能在新类中转调回设备，仍让设备决定一切。
- 每条路径只有一个明确授权的最终输入解析入口。迁移期间可以保留多个 producer，但不能各自隐式覆盖最终结果。
- 不把所有数据收集或缓存简单删除。性能改进应来自减少重复工作和明确复用条件，而不是牺牲对象覆盖。

### 2. 实际数据与证明一起移动

- 几何、索引、骨骼/世界矩阵、材质及 alpha 状态须携带各自来源、对象/部件身份、索引域、坐标空间、范围、代际与有效期。
- 最终采用另一份 VB、palette 或材质时，必须重新完成相应验证；不能保留旧来源标签冒充同一输入。
- 优先让校验入口签发构造受限、失效明确的凭据，消费者接口必须使用凭据才能取得对应数据；增加一个可被忽略的字段不算闭合。
- 不可变快照只能保证捕获后不变，不能证明捕获时正确；共享所有权只能保活其实际拥有的对象，不能证明原生裸指针或 GPU 物理存储有效。
- CPU 发布凭据、原生对象有效性与 GPU 消费许可分别证明，不能互相代替。

### 3. 分开处理不同寿命

- 区分不可变模型几何、同帧或有明确时限的姿态、地图/设备代际、上传槽和 GPU 消费者最后使用。
- 缓存键必须足以表达所缓存事实的相等性；摘要仅作查找提示，不能独自授权复用。
- 保留渲染所有者线程和 Present 安全点；producer 完成不等于消费者已用完，引用计数也不自动保护重定位前存储。
- 使用现有 DXVK 资源跟踪和同步机制。若确需增加边界，先证明其与现有所有权的衔接，不平行建立第二套释放系统。

### 4. 回退是明确状态，不是第二套隐式真相

- 来源失败、过期、域不符或范围不符时保持 fail-closed，并记录准确的拒绝阶段和理由。
- 保留当前已验证的兼容路径；覆盖、结果等价和必要实机门闭合后，才逐项退役旧路径。
- 必须同时检查合法对象的持续覆盖、阴影连续性及拒绝后的恢复，不能通过不提交 caster 或整场景无阴影获得“无坏帧”。
- 区分稳定产品、实验候选与待退役路径；实验开关应有默认值、责任模块、证据和退出条件，不成为永久无主分叉。

## 诊断与验证合同

### 可复现的实际输入

记录最终消费者实际使用的输入及其选择/回退原因，与帧号、对象、pass 和资源版本对应。
保留 source/build/DLL 身份与实际生效配置；DLL 哈希不能单独证明运行时开关已开启。
计数器用于定位规模，不能替代逐帧因果证据；缺失、截断、预算不足必须显式显示。

记录器的目标分工是：DLL 在显式启用和有界预算下自主完成基础录制、热键冻结与原始包导出；
Python 等外部工具负责可选的分析、视频和整理，基础证据导出不依赖其在线。
这是待实现目标，不是当前能力声明。实现时应复用现有录制核心，不另起一套数据格式或所有权。
导出不得阻塞渲染线程；内存/显存/IO 有明确上限、背压、失败提示和退出收口。
保留外部自动化接口，并为其连接失败、超时、退出和会话更换提供独立验证。

### 从纸面合同到真实交接

- 静态检查和独立算法模型仍有价值，但必须补足实际生产代码调用边界的正反例，不能只检查字符串存在。
- 合同变化须覆盖正常、无效、陈旧、失败回退、恢复和相关生命周期；共享测试应纳入项目维护的统一入口，避免只存在于手工命令中。
- 有条件时用同一捕获输入比较旧/新路径结果；涉及 Shader 时验证编译后布局、常量和必要数值结果。
- 明确区分构建、静态、CPU runnable、GPU 实机、玩家视觉证据，不把独立模型成功或隔离桌面成功外推为玩家接受。
- Shader 公共函数只合并已证明相同的语义，保留精度和运算顺序约束；不能在结构整理中夹带算法改变。
- 完整资源依赖图不是当前身份问题的前提。仅在真实跨 pass 依赖与所有权已清楚时逐步引入，不能把事件树改名当作资源图完成。

### 性能是约束，不是最后补测

对相关热路径记录修改前后完整帧耗时及 p95/p99、分配/大拷贝/锁次数、内存增长与回收情况。
诊断关闭的开销和开启后的有界成本分别报告；无法测量时列为未过门，不估算成已取得收益。
避免为每个 draw 新增堆分配、整对象复制、全局锁或同步读回；确有必要时须说明预算及实测依据。
诊断树应由顶层到子层闭合，明确 inclusive/exclusive 与未覆盖时间，禁止父子项重复相加。
比较保持对应 DLL、配置、地图、相机和显示条件一致；隔离数据不能冒充玩家前台 FPS。

## 当前问题的实施顺序

下表仅规定推进方向；具体修改、构建、部署与实机仍遵守当前用户授权和共享资源边界。

| 当前问题 | 顺带收紧的边界 | 不能省略的验收 |
| --- | --- | --- |
| 热键提示无后台连接、缺少有效坏帧包 | DLL 与可选外部工具分工、真实配置可见性、会话与退出 | 无 watcher 时仍能取得基础原始包；预算/失败提示正确；退出不挂住 |
| 高压地图裂缝及变换俯仰后的阴影消失/闪烁 | 最终蒙皮/阴影输入的来源、寿命和回退交接 | 坏帧关联输入；合法 caster 连续覆盖；俯仰往返后恢复；不能以全拒绝过门 |
| 尚未稳定复现的高压地图崩溃 | 资源申请失败、生命周期和异常证据的责任边界 | 完整自然故障证据；与未进图/调试器故障分开；未复现不是修复 |
| 后续模块维护 | 单一决策入口、兼容路径退役、实际交接测试 | 可独立比较与回退；覆盖和性能不过门不晋升 |

当前证据不足以把上述现象归为同一根因。已有累计拒绝和资源申请失败线索必须继续与实际故障帧关联，
不能直接等同于显存不足，也不能因为某一次未复现就认定问题结束。

## 每轮最小记录与发布边界

在 [开发日志](../agent-history/DEVELOPMENT_CHANGELOG.md) 的对应 checkpoint 写清：

1. 解决的用户问题和本次数据链/决策所有者。
2. 收紧了什么入口或生命周期边界，移除了什么旁路；若未调整，说明为何不适合本轮。
3. 实际验证、性能/覆盖/恢复结果，以及未覆盖条件。
4. 剩余债务、风险、再处理条件与下一步；文档之间链接，不复制大量历史记录。

可复现的诊断基线可以明确包含未解决缺陷；它不等于稳定发布基线。
只有组合候选通过相应实机与玩家视觉门，才允许按用户授权晋升并写入根 CHANGELOG。
本计划不改变已搁置的原版模型自动灯方案，不引入未完成 Water，不授权提交或推送。
