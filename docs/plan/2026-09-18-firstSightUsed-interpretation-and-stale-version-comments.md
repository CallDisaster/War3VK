## 3. 这是同一缺陷类的**第 3、4 次**

| # | 位置 | 形态 |
| --- | --- | --- |
| 1 | 读方 `:59`（round 70） | 注释说 **six** 结算桶，实际七个 |
| 2 | 测试 `test_independent_review…:55`（round 57） | 字面量绑定旧实参数 |
| 3 | **写方 `:63-66`（本轮）** | 注释说"只在版本 3 出现"，代码**无条件写** |
| 4 | **读方 `:220-221`（本轮）** | 注释说"只在版本 3"，实际 **v4 恒含** |

**共性**：改动时**只更新了代码**，或**只在后面追加了一段更正**却**没删前面那段**，
于是同一处上下文里出现**互相矛盾的两段注释**。

**可操作的规律（本轮提炼）**：改行为时，**搜索被取代的旧描述并把旧段删掉**，
而不是"在下面补一段新的"。补新不删旧 = 制造一处**自相矛盾**的现场。

## 4. 为什么不给这类问题加静态锁

- "注释是否与代码矛盾"需要**语义判断**，无法可靠地机械判定；
- 能机械判定的只有**具体字面量**（如 `firstSightUsed() ? 3 : 2` not in），
  而这类锁**已经存在** ✅；
- 强行扩大字面锁会不断产生**假阳性**（历史叙述里合法地提到旧形态）。
