# ⚠️ 修正② 的"前后对照"被 `INPUTS` 差异污染 —— 我自己的实验设计错误 — 2026-09-18

## 1. 发现的混淆

测阶段分布时看到剧烈变化：

```
BEFORE fix2 (cpu-10976, 总 3691):  Drawn=3172  Enqueued=455   FirstSight=64
                                   107 对象，平均 34.5 事件/对象
AFTER  fix2 (cpu-31168, 总 3648):  Enqueued=2683 Drawn=901   FirstSight=64
                                   64 对象，平均 57.0 事件/对象
```

`Drawn` 从 86% 降到 25%、`Enqueued` 从 12% 升到 74% —— **这个幅度不可能由修正② 造成**。

## 2. 原因：**两次运行的 `INPUTS` 不同**

| 运行 | 来源 | `DXVK_WAR3_FRAME_EVIDENCE_INPUTS` | 契约 |
| --- | --- | --- | --- |
| BEFORE `cpu-10976` | round 245 run A | **`1`** | `1` |
| AFTER `cpu-31168` | round 259 | **`0`** | `1` |

⇒ 我在 round 245 为了看 `skinPaletteSelection` 而开了 `INPUTS=1`，
本轮为了减少导出体积改成了 `INPUTS=0` —— **两次运行的参数不一致**。

⇒ **这个对照不是"修正② 前 vs 修正② 后"，而是"修正②前+INPUTS1 vs 修正②后+INPUTS0"**，两个变量同时变。

## 3. 哪些结论**仍然成立**、哪些**必须撤回**

### 仍然成立（这些是**记录器自身的计数器**，且与设计预期逐项吻合）

| 指标 | BEFORE | AFTER | 为什么仍可信 |
| --- | --- | --- | --- |
| `firstSightInserted` | 107 | 64 | 修正② 的定义就是"只有要发射才建条目" ⇒ `inserted == emitted` 是**直接后果**，不依赖 INPUTS |
| 假链签名 | 32 | 0 | 该形状的成因（未发射的首见条目走了 `:269` 的 false 分支）**已被结构性消除** |
| 解析器链数 | 107 | 64 | 同上 |
| `stageObservationComplete` | 32/107 | 64/64 | 同上 |
| 无链首的对象键 | 43 | 0 | 同上（这是修正② 的**定义性**后果） |

理由：`INPUTS` 只影响 draw 上**附加的诊断字段**（`inputSkinSelection` / `inputEvidenceProvenance`），
不影响 `NoteFirstSight` 的条目创建逻辑。而上述指标全部是"**条目/链的存在性**"指标。

### 必须撤回 / 不得引用

| 指标 | 撤回理由 |
| --- | --- |
| **阶段构成**（`Drawn`/`Enqueued` 占比） | **直接受 INPUTS 影响**，两次运行不可比 |
| 总 `emitted` 3691 → 3648 | 受"事件被发出去多少"影响，而 `Drawn` 条数在两次运行里差 2271 ⇒ 不可直接比较 |
| "平均事件/对象" 34.5 → 57.0 | 同上 |

**我在 round 259 的记录里引用了"总 emitted 3691 → 3648"作为"已知代价"的证据 —— 这一条不可靠，应撤回。**
（结论"预算紧张时对象不可见"仍由 `inserted 107→64` 支撑，但具体数字 3648 不可引用。）

## 4. 修正② 的核心结论**不受影响**

修正② 的预期是"**不再建零事件的条目**"，这直接体现为：

```
无链首的对象键  43 -> 0        （定义性后果）
假链签名        32 -> 0        （该形状被结构性消除）
chains         107 -> 64       （== inserted）
inserted == emitted            （新不变量）
stageObservationComplete 32/107 -> 64/64
```

这些都是**条目存在性**，与 `INPUTS` 无关。**⇒ 修正② 的验证结论保持成立。**

## 5. 要做干净对照的话

```
两次都用 INPUTS=0（或都用 1），其余参数完全相同，只有 DLL 不同。
但那需要一个"修正①only + INPUTS=0"的旧 DLL 采集 —— 旧 DLL（77CAEED9…）已被覆盖，
需从 c2 检查点的源码重建。成本较高；而修正② 的核心结论已由"条目存在性"指标充分支撑，
故本轮不再为此重建。
```

## 6. 教训（补进跨轮清单）

| 教训 | 实例 |
| --- | --- |
| **对照实验必须固定**所有**除自变量以外的参数，并逐项记录** | 我自己在 round 245 改了 `INPUTS`，round 259 忘了改回 ⇒ 两次运行不可比 |
| **比较"计数"类指标时，先确认它们的决定因素是否被自变量之外的东西影响** | `emitted` 受 DRAW 条数影响，而 DRAW 条数受 `INPUTS` 影响 |

**这是本项目里同一类错误的第 N 次**（前面有：c2 两次 `MATCH: False` 都是我的脚本错；
`pv[9]` 索引无根据；`OUTPUT` 环境变量被我当成布尔用）。
共同点：**我在"比较"或"解读"之前，没有先把"这两组数据除了我想比的东西之外是否一致"确认一遍。**
