## 用户目标与实现范围

让圣诞防守活动的风雪随音乐从小雪发展到暴雪。当前实现 12 个天气 JAPI、YDWE 分类、
单实例/64关键帧 CPU 时间线、GPU 程序化雪片与独立雪雾/低空吹雪。
音乐仍由原版 API 播放，作者在同一触发器启动/暂停/跳转天气；不是自动音频节拍分析。

不加入建筑自动厚积雪、屋顶碰撞、精确地形贴合或玩法风力，不扩阴影/Arena预算。
没有声明整项长期重构完成，也没有重新启动已延期的64位渲染宿主。

## 数据链与所有者

JASS 包装/严格载体 → 生产 Dispatch/统一句柄 → 固定容量 WeatherRuntime →
主渲染线程每帧/地图/设备一次按值快照 → 两个 GPU 消费者。
所有者实时诊断与渲染实际冻结输入分列；同帧三个域匹配后才能拼接雪片与雪雾命令证据。
旧句柄跨地图不复用；普通参数过渡连续积分风位移，Seek单独使历史失效。

雪片不上 shadowCasters/Stage11/Arena，不为大地图保存粒子快照；使用相机周边有界世界格子，
固定16,384实例。SnowPush 128B；按原深度合法采样/受32MiB当前分配限制的单张副本遮挡。
深度/颜色恢复精确布局，并以DXVK资源追踪保留至GPU完成。

雪雾复用既有体积实现但独立持有Medium网格、目标、UBO与历史，不改作者雾参数。
额外128MiB名义图像/缓冲预准入不是增加既有Arena预算；实际当前分配单列。
Driver内部与在途退役资源未计入，因此这些数字不等于整进程/显存峰值。

## 开发中实际发现与修正

- attachment-only深度不能直接采样：增加有明确读→写→读依赖的有界副本，不假定固定帧数退休。
- 半像素viewport差异、非法布局哨兵、窄深度范围按生产native映射收紧。
- 薄介质先裁剪eye→flake与天气盒，再用固定4点积分，不取地面终点雾量代替雪片终点。
- 低空吹雪不再乘Z-bottom羽化；风条带与雪片使用786432单位周期与有界位移。
- 当前在修天气资源异常隔离：准备阶段失败不得由外层永久关闭普通雾；录制阶段与device-lost不盲吞。
- 自动验收反例先实跑红灯，再收紧真实Launcher：空数据、错帧、假暂停、假关闭、重复截图均不能误通过。
