# Palette 对象证据：跨尝试误认证维护

状态：2026-09-22 源码维护，非画面修复或运行时验收。基线为主树 a2054a9 / v1.22.01。

## 反例与责任边界

旧记录器累计 sawServed/sawSubmit/sawDraw，只在判序时区分 attempt。
因而 R(A)→S(B)→E(C)→D(D)、未知尝试号、来源/hit 不一致都可能结算为 Recovered。
直接包含生产头的首轮 CPU 反例在旧源码上 32 个检查失败 24 个；这证明的是诊断误认证，
不等于新发现了游戏画面错误，也不证明游戏撕裂已经解决。

本批不改 palette 选择、caster 准入、渲染算法、GPU fence、内存预算或实验默认值。

## 唯一恢复证明

生产条目内按值持有 PaletteRecoveryAttempt；累计观察与当前证明分离。

- 同一次**已知** attempt 中必须顺序形成 S→E→D，来源一致且不是 None/Unknown，hit 相同且非零。
- UINT64_MAX 表示未知；0 合法。未知或切换 attempt 丢弃部分证明，A→B→A 不得拼回 A。
- 来源/hit/清空/缺前段错误在本次 attempt 内不可被重复事件洗掉；完整的新尝试可以重新建立证明。
- 已发生的全链顺序违规仍保守保留；原身份/代际/丢失门不放宽。
- 同帧重复只有在载荷、attempt、最后阶段一致且没有中间推进时才可合并。
  R→S/E/D→R、S→E/D→S 等不再被当成无害重复；计可见冲突并使当前证明失效。
- 终态 attempt 与实际 D 载荷取当前尝试，不混入旧尝试 draw。未知尝试仍保存实际观察，不能认证。
- FirstSight 保持观察链；ObjectGone/未闭合不冒充恢复。

## Wire 与读方

外层 schema 7 和 Kind::ShadowState / palette-object/v1 标签不变。
paletteObject 扩展版本升为 **5**：data[5] 是完整 64 位 attemptSerial；data[4] 仍为链型，
data[6..8] 保留零。读方必须顺序重建当前尝试而不是按 attempt 分组后拼接。
v1–v4 仍按原形状严格解析，但没有 attempt 关联证据，不再认证同对象恢复；保留阶段观察。
丢失、弱身份和未知代际依然导致未覆盖/未认证。

生产绘制点当前没有可靠 attempt 的情况继续记录 unknown，不能为了得到绿色结果填造帧号。
即使强身份合成测试可认证，生产缺少生命周期/代际等字段仍不得外推认证。
“Drawn”只表示绘制命令被记录，绝不是 GPU 完成或像素正确性。

- AutoTest/test_palette_attempt_production.cpp：真实记录器的正例、跨尝试、重试、未知、同帧回退及终态关联。

- 两个正式 Python 读方及旧版夹具回归；静态守卫不替代生产测试。

固定 1024 条目表，不新增逐事件堆分配，不新增矩阵扫描/查询/渲染锁。
