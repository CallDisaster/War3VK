# 1.27a 单位移动 Walk 自动重选：逆向与候选边界

日期：2026-09-23。目标是在不覆盖原版动画 Native 的前提下，为单位提供「移动时暂不自动循环 Walk / 恢复自动 Walk」开关。此文是逆向和源码候选记录，不是游戏内验收。

## 证据链

- DSH 会话 `session-93b4c07d-de1f-49e3-b565-8bf78e58e4bc` 使用 `commandcode/deepseek/deepseek-v4.1-flash` 先做机械定位；它只提交候选地址和调用关系，没有修改 IDA 或产品源码。主线程随后在 IDA MCP 独立复看反编译、交叉引用与调用点，并核对本机两份 `Game.dll`。两份本地文件 MD5 均为 `267861a0dfd416dbad13e7ee3ec7794a`、大小 13,187,048 字节；其他发行物不能直接继承这些偏移。
- 原版 `SetUnitAnimation` 由 `Game.dll+0x1F7230` 经 `+0x1F7280` 进入 sprite 动画入口 `+0x186590`；`SetUnitAnimationByIndex` 从 `+0x1F7250` 到 `+0x186820`。`QueueUnitAnimation` 是另一路 `+0x1F26F0`。因此只拦截全部属性 5 请求会误伤原版脚本播放，不能采用。
- 两个移动状态回调分别位于 `Game.dll+0x64C6A0`、`+0x64C780`。它们检查运动状态；进入移动且当前属性不是 5 时，通过 CUnit 虚表 `+0x8C` 请求属性 5（Walk），参数为 `(5, 0x40, 1)`；停止移动时可请求属性 4（Stand）。实际调用指令地址为 `+0x64C752` / `+0x64C891`，返回地址为 `+0x64C754` / `+0x64C893`。两处调用后均有 `fstp st`，说明被调方法必须交付有效的浮点返回值。
- CUnit 虚表目标为 `Game.dll+0x67BB90`；它继续调用 `+0x6A0AE0`，后者返回浮点结果。以上调用图由 DSH 初查和主线程 IDA 复核共同支持；尚未在运行时用命中计数证明这两个回调覆盖了所有可能的自动 Walk 路径。
- 主线程在当前 IDA 数据库中重新读取两处调用字节 `FF D0 DD D8` 与目标序言 `55 8B EC 83 7D 10 00 56 8B F1 74 08`，均与候选守卫一致；已给上述三个地址写入带置信边界的 IDA 注释，便于后续复审。

## 候选行为与证明上限

2026-09-24 按作者要求移除额外环境变量门：目标序言与两处调用指令匹配时安装 Hook；不匹配时不安装并保持原版行为。Hook 只在上述两处返回地址、属性 5、标志 `0x40`、reset `1` 同时成立，并且被关闭的 CUnit 指针与实时 JASS handle→CAgent→CUnit 三者仍相符、单位未死亡时，才跳过该次自动 Walk 请求并返回 `0.0` 浮点值。其余动画请求原样调用 Game.dll。开关状态受限于当前 JASS/map 会话，并在 VM 重建时清除。无额外配置不等于已通过游戏内验收。

JASS 候选为 `WarVKSetUnitWalkLoopEnabled(unit, boolean)`；两个 Override 助手先关闭自动 Walk，再调用原版 `SetUnitAnimation` 或 `SetUnitAnimationByIndex`；`WarVKClearUnitMovementAnimationOverride` 恢复自动 Walk。它不暂停单位移动、冻结动画时钟或保证非循环动画结束后显示哪一帧。

未闭合：真实游戏中 Hook 命中与 ABI、移动中播放指定动画的持续性、死亡/销毁/句柄复用、换图后重置、编辑器与高压地图、关闭功能时零行为回归。单靠反编译、编译或宿主机策略测试，不能宣称 API 已可用于发布。

当前状态表最多保存 512 个被关闭的单位；已失效句柄在同地址再次触发回调时会被移除，JASS VM 重建会全表清除，但尚无独立的单位销毁通知。因此高周转、长时地图的满表行为仍需实机观察；满表时新请求明确失败，不会默默接管其他单位。
