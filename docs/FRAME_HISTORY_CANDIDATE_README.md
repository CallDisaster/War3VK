**不是稳定发布版；撕裂未解决，完整GPU取证尚未完成。不要上传为正式Release。**

本包保留同步优化、异步截图、退出修正、太阳API及Froxel/局部雾集成候选；未合入未完成的
Water分支。原版模型自动点光和接管点阴影已按用户决定默认关闭；现有作者显式点光不受影响。

## 本次实际完成

- CPU事件环、会话隔离、触发后窗、冻结导出；默认关闭。
- Present/渲染pass/相机/阴影状态、级联矩阵；独立可选normal caster输入元数据。
- 当前启动器还启用最终方向阴影draw状态：实际Alpha参数、纹理视图、VB/IB范围、MVP和
  表面CSM/体积太阳路径标记；用独立cell并发队列避免高密度记录争用一把全局锁。
- GPU最终彩色图像环：启动器默认请求256帧前窗+4帧后窗，按至少1秒时间保留；
  2560×1440最大约3.57GiB图像预算（3.83GB），并检查显存余量。实际导出窗口由时间和预算共同决定。
  采集时显存内copy，无持续磁盘写入或CPU读回；触发后才使用已有三槽异步读回/保存。
- Ctrl+Shift+C在真正安装的War3窗口过程触发；不是系统全局热键，也不会占用后台桌面输入。
  HUD会显示“未启动/正在准备/采集中秒数/已触发/保存进度/失败原因”。
- 单张截图/历史窗口可按精确frame/Present/epoch/完成值关联，漏帧/失败不静默忽略。

## 严格限制

- 窗口按时间而非固定帧数验收；默认目标至少1秒。在高FPS下会保留约130帧，
  但仍受4GiB上限和显存余量限制；错过反应窗口可能没有保住异常。
- 尚无CSM/scene-depth/当前与历史vis/雾前后等GPU图像历史、每draw ID像素归因、完整
  GPU几何/纹理/动态palette字节字典。原始颜色图及CPU元数据不能代替这些内容。
- 当前仅手动触发，无启发式视觉自动检测。根`captureComplete=false`与`rootCauseReady=false`
  是真实状态，不是可忽略的提示。不要求玩家马上再费力找一次稀有样本。
- 初始化环会分配显存，有一次性开销；持续copy也有GPU带宽成本，尚未做前台性能验收。
  若慢写者被整圈追上，单cell保护会明确拒绝覆盖，不能称永远零丢失/零开销。
  切图、Reset或分辨率变化会拒绝/取消当前会话。
- 初版仅B8G8R8A8单采样二维最终颜色；不支持的格式不会伪造成功。

## 若主动试用（非必须）

1. 完全退出游戏，备份自己游戏目录的`d3d9.dll`，手动放入本包DLL；没有任何自动部署。
2. 保持`AutoTest/`内脚本在一起。需要本机Python、Pillow和numpy；当前研发机器已有。
3. 在PowerShell运行：

   ```powershell
   .\AutoTest\launch_frame_history_player.ps1 -GameDir 'E:\Work\Warcraft III'
   ```

4. 正常进入地图，保持2560×1440。无需性能录制、无需灰度阴影因子。待后台watcher完成arm后，
   看到异常立即按`Ctrl+Shift+C`一次。不要立刻退出，等待HUD提示调试包已保存（约1–2GB图片）。
5. 输出在游戏目录`WarVK/Log/FrameEvidence/history-.../`；watcher状态在同目录`watch-.../`。
   上传/交接应保留整个目录，不仅拿一张图。脚本不自动重新arm，不删除旧证据。

启动器不修改MPQ/地图、不结束现有游戏/编辑器，也不更改系统级环境变量或注册表分辨率。
辅助Python进程隐藏窗口，不留下等待输入的命令行；失败可查看`watcher-error.log`。
`slot-N.tga`的文件名不是时间顺序，**必须按manifest中的ordinal顺序**查看。
